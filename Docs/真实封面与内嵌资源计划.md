- [x] 核对服务端 cover_id、受鉴权的 GET /api/v2/covers/{id}，歌词使用曲目元数据 lyrics。
- [x] 读取已下载曲目的内嵌资源，支持普通文件和 Android 文档目录。
- [x] 封面优先使用内嵌图片，缺失或无效时请求服务器封面，均不可用时回退名称色块。

## 实现与验证记录

2026-11-13 完成应用内真实封面接入。

- 普通文件在 Dart isolate 中按文件内容识别格式，Android 文档 URI 通过已有原生复制能力生成临时文件，解析结束删除副本。回归测试覆盖了此路径并修复临时目录创建问题。
- 先读取有效内嵌图片，缺失或无法解码才使用服务端 cover_id。未下载的音频直接使用服务器封面，下载完成后优先重新读取内嵌封面。歌单采用首个可用曲目的内嵌封面，服务器回退优先使用歌单 cover_id。
- 请求合并，成功结果内存缓存最多 64 项，磁盘图片缓存上限 64 MiB，单图上限 8 MiB。缓存键隔离服务器、凭据和元数据版本，普通文件还包含修改时间与长度。失败结果一分钟后可重试，网络变化可立即重试。
- 服务端请求沿用 API Key 鉴权，禁止跟随重定向，沿用移动网络下载策略。已缓存图片可离线使用，凭据及授权变化后阻止旧请求结果显示。
- 应用内曲库、歌单、曲目列表、播放栏、完整播放页、队列均接入共享封面组件。载入及失败时使用名称色块，切换来源期间清除旧图片。
- 六项资源测试及一项图片组件测试加入，全量 116 项测试与静态分析通过。实际合成 MP3、FLAC、M4A 改为 .media 扩展名后均成功读出内嵌封面。
- 内嵌 USLT 歌词提取已由回归验证，歌词页面、滚动定位及服务端歌词显示在后续实现。当前系统媒体通知封面尚未接入本模块，应用内显示已完成。Android 实机目录和实际曲库仍需跟进验收。

解析依赖为 [audio_metadata_reader 1.8.1](https://pub.dev/packages/audio_metadata_reader)，封面权限协议参考 [Pikmelo Server 源码](https://github.com/ShenYunyao1/Pikmelo-Server/blob/main/server/internal/music/cover_access.go)。

最终 Windows release 与 Android 三架构 release 构建通过，Android 包分别约 24.0 / 27.1 / 29.2 MB。本轮交付为本地构建与源码提交，实机及实际曲库显示继续验收。
