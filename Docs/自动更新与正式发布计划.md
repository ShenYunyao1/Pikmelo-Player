## 文件与完成标准

共享代码放入 `lib/updates/`，设置页和应用装配接入更新控制器。Android 原生适配放入现有 Kotlin 包，发布流程放入 `.github/workflows/`，发布元数据工具放入 `tools/`。正式密钥与备份位于工作区外，仓库保留证书指纹及配置模板。

验收使用相同 applicationId 和正式签名的两个递增版本。Android 根据 PackageInstaller 返回结果完成免确认更新或用户确认流程，升级保留原应用数据与目录授权。既有开发版使用 debug 签名，正式签名基线独立安装。Windows 本轮接入版本检查与发布入口，Android 执行应用内下载及安装。

Android 免确认更新条件随系统版本变化，安装流程始终处理 `STATUS_PENDING_USER_ACTION`。[Android PackageInstaller 官方文档](https://developer.android.com/reference/android/content/pm/PackageInstaller.SessionParams#setRequireUserAction(int))

GitHub Releases 资产提供版本、下载 URL、长度和 SHA-256 digest，客户端同时校验固定正式签名证书。[GitHub Releases 资产文档](https://docs.github.com/en/rest/releases/assets)

### 发布与密钥恢复

1. 递增 `pubspec.yaml` 的版本名称与构建号，正式发布使用递增构建号。
2. 提交并推送源码，推送对应 `v版本名称` 标签，GitHub Actions 分别构建 Android 三架构 APK 与 Windows ZIP，统一校验并发布 Releases。
3. 本地构建将环境变量 `PIKMELO_SIGNING_PROPERTIES` 指向工作区外的 `signing.properties`，该文件包含密钥路径、别名和密码。
4. 恢复时从备份目录复制 `release.p12` 与 `signing.properties` 到受限目录，调整配置内的密钥绝对路径。导出证书计算 SHA-256，与 `android/release-cert.sha256` 比较后再构建。已通过备份密钥重新导出证书并比较一致。

主副本与备份位于本机不同磁盘路径，本轮未创建异机或离线介质备份。
