# 三行歌词设计方案 V1

2026-11-13，用户已确认并进入实施。交互预览见[三行歌词预览](三行歌词预览.html)。

## 已确认需求

- 正在播放页显示上一句、当前句、下一句，对应淡出、高亮、淡入。
- 本地歌词优先读取已下载音频的内嵌歌词，缺少有效内嵌歌词时从服务器获取。
- 延续现有配色、单行曲目信息及底部固定的进度、码率和居中播放控制。

## 参考与采用方式

- Apple Music 的 Android 歌词界面采用按播放时间逐行推进，缺少同步歌词时可显示全文。采用当前句突出、时间状态明确的阅读层次。[Apple 官方说明](https://support.apple.com/en-us/109355)
- Namida 的 Flutter 源码将歌词获取、文本和同步数据、播放位置监听与行切换分开管理，按当前行变化更新显示。采用相同的模块职责，来源顺序遵循本项目需求。[歌词控制器](https://github.com/namidaco/namida/blob/main/lib/controller/lyrics_controller.dart)、[歌词视图](https://github.com/namidaco/namida/blob/main/lib/packages/lyrics_lrc_parsed_view.dart)
- AMLL 将时间化歌词数据和渲染组件分开，支持行级与逐字数据。参考其当前行阅读重点和过渡思路，采用 Flutter 原生的三行实现。[AMLL Core](https://github.com/amll-dev/applemusic-like-lyrics/blob/main/packages/core/README-CN.md)

以下尺寸、颜色和过渡是针对 Pikmelo Player 的设计选择。

## UI 布局

```text
                正在播放

                当前封面

  曲目名称（单行滚动）
  歌手（单行滚动）
  专辑（单行滚动）

            上一句，逐渐淡出
          当前一句，薄荷绿高亮
            下一句，渐渐进入

  已播放时间 ──────── 总时长
  320 kbps
  音量 模式   上一首 播放 下一首   队列 空位
```

- 歌词区域采用约 120 dp 的固定高度，三个位置的中心间隔约 36 dp，居中显示。上下边缘作透明度渐变，歌词区随大字体适当增高。
- 当前句使用薄荷绿 #92DFC0，20 sp、半粗体、100% 不透明度。上一句约 18 sp、25%–35% 不透明度，下一句约 18 sp、45%–55%。静止时上下句仍可阅读。
- 换句时整体向上移动一个位置，当前句进入上一句位置并变淡，下一句进入中央并高亮，新的下一句从下方淡入。过渡约 260 ms，快速连续句按间隔收短过渡。
- 拖动进度或跨多句跳转时直接定位到目标三句，随后恢复普通换句过渡。暂停时固定当前内容，切歌立即清理旧歌词并加载新曲。
- 每句占一条视觉行。超长当前句复用已优化的绘制层横向滚动，上下句使用省略显示。歌词区高度固定，加载、缺失和换句均使用同一高度。
- 优先占用曲目信息与进度条之间的留白。小屏根据剩余高度调整封面与垂直间距，上方封面和信息区域可滚动，歌词区域及下方播放控制保持可见。

## 其他显示状态

| 状态 | 表现 |
| --- | --- |
| 首句前 | 上一句留空，中央显示前奏，下一句预告首句 |
| 同步歌词播放中 | 固定显示上一句、当前句、下一句 |
| 最后一句 | 下一句留空，歌曲结束时结束当前高亮 |
| 有明确时间标记的空白段 | 中央显示间奏，按时间保留停顿 |
| 正在读取 | 中央显示正在读取歌词，区域尺寸固定 |
| 无有效歌词 | 中央显示暂无歌词 |
| 有纯文本歌词 | 标注未同步歌词，在同一区域手动滚动阅读 |
| 暂时离线且无缓存 | 显示歌词暂不可用，恢复网络后可重试 |
| 系统减少动画 | 按行切换高亮，直接更新位置 |

内嵌纯文本属于有效内嵌歌词，优先展示该内容。同步时间依赖歌词本身的标记，纯文本采用手动阅读。

## 来源、缓存与协议

1. 当前曲目有可用本地音频时，复用 EmbeddedResourceReader 在 isolate 中读取内嵌资源，兼容普通路径和 Android 文档目录。
2. 有有效内嵌歌词时直接使用，解析成带时间的文档或纯文本文档。
3. 缺少有效内嵌歌词时，读取已同步并按服务器及凭据隔离保存的 Track.lyrics。该字段本身来自服务器。
4. 本地没有服务器歌词且同步状态过期时，合并一次现有 GET /api/v2/sync 鉴权刷新，再检查曲目歌词。刷新按连接合并与限流，结果为空采用短期负缓存。
5. 内嵌和服务器结果分别缓存。内嵌缓存按媒体路径、文件指纹及解析版本失效，服务器缓存按服务器、凭据指纹、曲目 ID 和元数据版本失效。文件下载完成后重新检查内嵌，内嵌优先级高于服务器缓存。

已核对服务器 Track 的 lyrics、embedded_lyrics 和 lyrics_source 字段，以及项目中已实现的同步读取。歌词元数据请求沿用现有 API Key、连接状态和重试控制，更新包策略独立，曲目禁止下载策略继续约束音频下载。歌词查询属于曲目元数据同步。[服务端曲目模型](https://github.com/ShenYunyao1/Pikmelo-Server/blob/main/server/internal/music/types.go)、[服务端歌词解析](https://github.com/ShenYunyao1/Pikmelo-Server/blob/main/server/internal/music/lyrics-parser.js)

当前 audio_metadata_reader 1.8.1 已提供 USLT、Vorbis 和 M4A 等文本歌词读取，项目 USLT 回归通过。SYLT 同步帧需要额外适配及真实样本验证。ID3 标准分别定义 USLT 与 SYLT，内嵌文本也可能包含 LRC 时间标签。[ID3 官方规范](https://id3.org/id3v2.3.0)

### 解析与定位

- 支持 LRC 的分秒标签、1–3 位小数、同一行多时间标签、offset、BOM、CRLF 和元数据标签。时间偏移规则与现有服务器 lyrics-parser.js 对齐，正 offset 提前显示，使用共同样本验收。
- 时间排序后按同一时刻分组，首条有效文本作为主句，同时间附加文本保留在文档中。三行视窗依时间组推进，避免原文与译文被当成连续时间段。
- 保留有时间的空白行，区分前奏、间奏与普通空白。首句前索引为 -1，二分定位最后一个 start 小于等于当前位置的时间组。
- SYLT 先覆盖可验证的毫秒时间格式。其他时间单位结合音频信息换算，无法可靠换算时作为纯文本展示，解析状态有明确记录。

### 更新与性能

- 每次切歌使用服务器、凭据和曲目标识生成请求版本，异步完成时再次核对，丢弃过期结果。
- 播放进度更新只校准时间与查找行索引。歌词文档在曲目、文件或服务器版本变化时重新加载和解析。
- 当前句变化时构建三行快照，换句动画通过独立绘制区域完成位移及透明度变化，复用预排版文本。
- 可按下一条时间标签安排一个轻量计时器，并以引擎实际进度持续校正；暂停、缓冲、停止和切歌会取消旧计时器。拖动进度后立即重新定位。
- 动画仅在换句期间运行，最多绘制三个可见位置和过渡需要的相邻句。封面、曲目信息和底部控制区分别隔离重绘。

## 实施结果

### 模块与数据

- `lib/lyrics` 包含不可变歌词文档、LRC 解析、来源仓库、播放同步控制器和三行组件。共享模块由 Windows 和 Android 复用。
- 内嵌读取复用封面及元数据的串行资源读取器。新增 ID3v2.2 / 2.3 / 2.4 SLT / SYLT 解析，支持毫秒与可换算的 MPEG 帧时间，无法确定帧时长时保留纯文本。
- 自动化样本覆盖 MP3 USLT、SYLT、UTF-16、FLAC Vorbis Comment 与 M4A `©lyr`。测试目录的两份静音音频由 FFmpeg 合成，仅包含示例文本。
- 内嵌纯文本优先于服务器同步歌词。成功的本地结果按文件指纹持久化，读取失败可重试，删除媒体时同时清理歌词记录。
- 服务器歌词的缓存版本使用原始同步记录，本地专辑、标题等元数据解析不会误使缓存失效。已验证先获取服务器歌词、下载音频并补齐本地元数据、随后离线重建客户端的读取流程。
- 已同步的服务器歌词可离线读取。缺失时使用现有 `GET /api/v2/sync` 只读分页，合并并发请求，并按服务器和凭据隔离缓存。该过程保留现有下载管理器。
- 下载完成或音频来源变化、曲目元数据变化、网络恢复及手动重试会重新核验歌词。凭据、授权或文件来源在异步请求期间变化时丢弃旧结果。

### 播放页

- 歌词置于曲目信息与固定底部控制区之间，普通窗口约 120 dp。紧凑横屏按可用高度压缩行高和字号，上方封面及信息可以滚动。
- 正常换句通过 Flow 绘制层完成约 260 ms 的位移、透明度与缩放。拖动进度和跨句跳转直接定位，暂停、缓冲和停止取消下一句定时器。
- 当前长句复用绘制层滚动文字，上下句保持单行。减少动画设置生效时直接切换并省略长句。
- 无歌词、加载中、读取失败重试和未同步全文均使用固定区域。前奏、带时间空行对应的间奏及播放结束有明确状态。

### 诊断与交付
